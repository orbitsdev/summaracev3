Data schema

Data Schema Document

SummaRace v3 · version 1.3.6 · this replaces a "backend schema": the game has no backend

1Overview

This document says where SummaRace's data lives, how it is structured, who can see it, and how the pieces connect.

There is no server and no database. Story content is a JavaScript file shipped in the app. Learner progress and results are saved in the phone's WebView storage (localStorage). The only way data leaves the phone is when the teacher copies, downloads or shares the CSV.

2Data model

3Story content: stories.js

window.STORIES is an array of 30 objects, sorted by id when the game starts. Every story has 5 pages, 5 page questions with 3 options, a main idea question with 4 options, and 5 SWBST parts with 1 right and 2 wrong answers.

textstring[5]The 5 pages the learner reads.
quizQuestion[5]One question after each page. why is the page text that holds the answer; it is used to highlight the right part when the story is shown again.

mainIdeaTextstringThe main idea in words; allowed vocabulary for the summary.

4Saved data: localStorage

KeyValueWritten when
summarace.v1{profiles: {id: Profile}, current: id | null, log: Record[]}A learner signs in, finishes a level, or the teacher erases or restores.
summarace.v1.pref{voice: bool, sound: bool, music: bool} (all true by default)A switch in Settings changes.
summarace.v1.runner"boy" (Max) or "girl" (Mia)The runner is picked on the race start card.
summarace.v1.erasedA full copy of summarace.v1 from just before the last eraseThe teacher types ERASE. Removed again by "Bring back erased records", which merges it with anything recorded since.

An unfinished level is never saved: quitting mid-level leaves no record. If storage is blocked or full, the game keeps working for the session but nothing is kept.

5CSV export format

File name summarace-records-YYYY-MM-DD.csv, UTF-8 with a byte-order mark (so Excel opens it correctly), comma separated, one header row, then one row per finished level, oldest first. Values with a comma, quote or line break are wrapped in double quotes. The column order is fixed:

5level1–30Story id.

13summary_triesnumberScored summary checks (early checks like "too short" don't count).

6Access control

WhoStory contentOwn progressOther learnersRecords / CSV
LearnerReadRead, add by playingSees names in "Or continue as"Can open Teacher records (no password)
TeacherRead—Sees all on the phoneCopy, download, share, erase (type ERASE), restore
Anyone with the APKRead (the files are inside the app; the repo is public)Nothing: data stays on each phone

There is no password on Teacher records. This was a choice for a classroom tool; the ERASE word and the undo protect against accidents, not against a learner who wants to look.

7Data storage

Where

WebView localStorage inside the app's private folder. Clearing the app's data or uninstalling deletes it.

Export

Android 10+: Download/SummaRace via MediaStore. Android 7–9: Download/SummaRace with storage permission. Or Share / Copy.

Backups

None automatic. The teacher should export the CSV after each session.

Personal data

Only the name and section typed in, and the summaries. Nothing is sent anywhere.
